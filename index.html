Furby DLC Workshop

A local-first workbench for inspecting a known-good Furby Connect DLC and preparing eye frames, 6-bit palettes, audio, lip-sync cues, and movement notes. This is an early prototype: it exports diagnostics and project data, not a guaranteed flashable DLC.

1. Known DLC Library

Choose the bundled reference DLC or upload another .dlc file. This DLC was tested by the user on a real Furby and confirmed to play successfully.

Bundled DLC loads when selected.

Choose a DLC and press Inspect. The parser checks the common FURBY signature and looks for the resource directory. Unknown layouts are reported rather than guessed.

Flash DLC

Connect to a nearby Furby Connect over Bluetooth LE, send the selected .dlc using the FurBLE transfer protocol, verify its checksum, then load and activate it. Use Chrome/Edge on HTTPS or localhost.

All preview canvases are quantized to the selected 6-bit mode (64 grayscale levels or 64 levels per RGB channel). Image display duration is recorded in the project manifest; it does not yet alter proprietary DLC timing. The diagnostic exporter quantizes pixels to 0–63. Exact CEL headers, transparency rules, cell ordering, palette packing, and separate-eye resource mapping still need confirmation. GIF preview currently uses the first decoded frame.

3. Audio bank and clip settings

A18 files are treated as encoded bytes; this page does not decode or resample them. WAV/MP3 files are retained as source assets in the project manifest.

4. Lip-sync cue editor

Add time-stamped cues for later mapping to the real LPS format. Cue labels are project notes only until the LPS record layout is verified.

5. Servo movement timeline

Time is when to trigger a predefined servo movement after the animation begins. The selected movement ID represents a built-in movement; this editor does not set a custom travel time or target position.

Choose one of the 12 servo movement IDs (0–11).

6. Other resources / project export

Attach known-good resources to keep a record of them. They are included in the project manifest as filenames and metadata; this prototype does not inject unverified bytes into proprietary resources.
